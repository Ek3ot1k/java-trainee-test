# Правила выполнения

## Время

Срок выполнения — **1–2 календарных дня** с момента получения задания, включая Code Review. Самостоятельно распределите время внутри этого срока. Если не успели закончить, отправьте рабочую часть и перечислите в README:

- что осталось;
- почему не успели;
- как планировали завершить.

Незавершённое, но понятное решение не означает автоматический отказ.

В идеале к окончанию срока проект должен запускаться по README на чистом окружении. Перед отправкой самостоятельно пройдите инструкцию запуска, примените миграции, сделайте хотя бы один API-запрос и запустите тесты. На интервью вас попросят продемонстрировать это с помощью screen sharing и объяснить код.

## Разрешённые источники

Можно использовать:

- Google и другие обычные поисковые системы;
- Stack Overflow;
- официальную документацию Java, Spring, PostgreSQL и используемых библиотек;
- IDE autocomplete и локальные инструменты разработки.

Нельзя использовать ChatGPT, Claude, Gemini, GitHub Copilot, Cursor и любые другие генеративные AI-инструменты. Мы не используем автоматический «детектор AI-кода»: авторство и понимание решения проверяются в разговоре и небольшой совместной доработке.

## Git

Ведите работу в Git. Желательно сделать несколько логических коммитов, которые отражают этапы решения. Идеальный Git Flow и большое число коммитов не нужны.

История нужна не для формальности: она помогает понять ваш процесс, приоритеты и то, как менялось решение. Единственный коммит `final solution` не запрещён, но даёт мало информации и будет слабым сигналом инженерной аккуратности.

## Самостоятельные решения

Если требование допускает несколько вариантов, выберите один и кратко объясните его. Если обнаружили неоднозначность — зафиксируйте своё предположение, не пытайтесь угадать «секретный правильный ответ».

Можно смотреть документацию. Мы проверяем не память на аннотации, а способность разобраться и сделать связное решение.
